# 服务器地址变更与本地环境接续

服务器身份和连接地址是不同概念。支持身份验证的新客户端登录时发送随机挑战；新服务器返回 Ed25519 签名的挑战、确认的用户名和持久用户 ID。客户端首次成功登录时固定身份，之后相同密钥与用户 ID 可以在新 IP、域名或 FRP 路径继续引用原有本地数据。

## 服务端部署与备份

- `SERVER_IDENTITY_FILE` 默认是 `USERS_FILE` 同目录的 `server_identity.json`，首次支持此协议的登录生成，文件权限为 `0600`。
- 必须与 `users.json` 一起持久保存和备份。身份文件包含私钥，不得放入源码、公开下载、日志或发送给客户端。
- 更换入口、主机迁移和恢复原服务器时保留两份数据。创建另一个独立团队时不能复制原团队的身份密钥和用户身份；否则会被视为同一团队。
- 已有持久用户 ID 但身份文件丢失时，新协议登录停止并要求恢复备份，不能静默生成替代身份。密钥轮换和账号改名不自动接续旧数据，需要独立迁移。
- 首次连接依然需要可信地址，推荐 HTTPS。身份签名不加密 HTTP 中的密码、令牌或内容，也不能替代 TLS；已信任的入口缺少证明或身份改变时，新客户端停止接续。

## 旧版本兼容

旧客户端不发送挑战，登录响应和其余接口保持原合同。新客户端连接未升级的服务器时继续按规范化 URL（含路径）和精确用户名隔离。已固定身份的客户端不接受身份验证降级。

旧客户端依然以地址区分数据，因此自动跨入口接续需要双方支持新协议。此前仅按地址保存的环境不能仅凭相同用户名自动合并。

## 显式接续旧地址的数据

迁移前退出应用，明确旧地址、新地址和精确账号，先备份本地 `settings.json`。调用设置身份模块的 `linkPrincipalEndpoint` 只新增本地地址到原存储身份的直接关联，不复制、改名、删除任何 Chromium 分区，不覆盖新地址此前的数据。

设置内的 `principalSettings.endpointAliases` 是主进程管理的迁移记录。归属不匹配、不同已固定服务器身份或已有冲突关联时拒绝迁移；不得通过修改记录绕过检查。恢复时在应用退出后使用迁移前的设置备份；迁移之后新增的设置需要单独保留。

此接续适用于已确认同一服务器、同一账号的入口变更，不适用于个人与团队之间、不同团队之间共享网页会话。授权仍须从当前入口重新取得，旧网络授权不能当作继续访问的证明。
